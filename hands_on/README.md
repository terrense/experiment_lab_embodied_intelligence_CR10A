# 上手体验：自己打开 MuJoCo，看 CR10A 怎么规划、避障、跟踪

> **全部是仿真。** 这里的每个程序都只在电脑里运行，**不会连接真机**，也不会用到 `ex_dobot_motion`。
> 唯一和真机相关的是体验 5：它使用从真机数据辨识出来的动力学参数，但运行时完全离线。

## 怎么打开

两种方式，效果一样：

- **双击**：在资源管理器打开 `C:\Users\HGDOCTOR\embodied-x\hands_on\`，双击对应的 `.bat` 文件。会弹出一个黑色终端窗口，然后 MuJoCo 窗口自己打开。
- **命令行**：在 Windows 终端执行 `wsl -d EmbodiedX-Humble`，然后：
  ```bash
  cd /mnt/c/Users/HGDOCTOR/embodied-x && source scripts/ex_env.sh
  cd learning && python3 -m ex_learning.view_policy --task wall --policy apf
  ```

如果后台在训练 PPO，体验 4 和 5 会变卡，因为它们要求物理仿真实时运行。最好等训练结束再玩这两个。体验 0–3 不受影响。

## 体验清单（建议按顺序）

| # | 双击 | 你会看到 | 看点 | 时长 |
|---|---|---|---|---|
| 0 | `0_free_reach.bat` | 空场景，绿色小球是目标 | 经典 DLS 雅可比控制器直接伸手过去。没有障碍时它 100% 成功，这是"基线先于 RL"的那个基线 | 约 1.5 分钟（20 个回合） |

| 2 | `2_straight_line_hits_wall.bat` | 同一面墙 | 直线控制器直接撞墙，撞上的瞬间**目标小球变红**，回合结束 | 约 1 分钟 |
| 3 | `3_ppo_policy.bat` | 同一面墙 | 训练好的 PPO 策略。和体验 1 对照着看，它绕墙的方式和 APF 不同 | 约 2 分钟 |

| 5 | `5_identified_dynamics.bat` | 同体验 4 | 换成**真机辨识**出来的动力学（质量 ×1.64、真实的摩擦）。对比体验 4 的跟踪误差数字，看看它变大了多少 | 同上 |

体验 0–3 的终端会逐个回合打印结果：`success`、`missed by 34 mm`（时间到了但没到达）或 `COLLISION ('Link4', 'wall')`（哪个连杆撞上了哪个障碍）。成功的判定标准是：4–6 秒内 TCP 到达目标 2 cm 以内，并且全程没有碰撞。

## MuJoCo 窗口里能做什么

**我实测过的：**
- `Tab` 收起或展开左侧面板，`Shift+Tab` 收起或展开右侧面板。两侧都收起后只剩 3D 画面。
- 右侧面板点 **Joint** 展开，显示 6 个关节的实时角度（弧度）。点 **Control** 展开，显示 6 个电机的实时力矩（N·m）。看机械臂加速、减速时，力矩会跟着跳动。
- 演示播完后会自己退出（退出码 0），终端提示按任意键关闭。

**MuJoCo 的标准操作，但我没法用自动化可靠地测试鼠标，请你上手时顺便确认：**
- 左键拖动旋转视角，右键拖动平移，滚轮缩放，双击选中一个连杆。
- 点窗口右上角 × 提前关闭。我修过一个问题：这个查看器在 WSLg 下关闭时会段错误（exit 139）。程序自己退出的路径已经修好并验证过，但**点 × 的路径我没能测到**。如果点 × 后终端出现 `Segmentation fault`，那就是这个已知问题，没有危害，告诉我一声就行。

**有意思但要注意的：** 右侧 **Joint** 面板里的滑条可以直接拖动，相当于把关节**瞬移**到新的角度。演示过程中拖一下，会看到伺服拼命把关节拉回去。我测试时误拖了一下，J2 的力矩直接打到了 −300 N·m 的上限。这只是仿真，可以放心玩，就当感受一下伺服的"倔强"。

## 出问题时
- **窗口没弹出来**：WSLg 偶尔会卡住。先双击 `9_stop_everything.bat`，再试一次。还不行就在 Windows 终端执行 `wsl --shutdown` 后重试。注意这会同时停掉正在跑的训练。
- **体验 4 报 `start failed`**：多半是上一次的进程没关干净，双击 `9_stop_everything.bat` 后重试。日志在 WSL 里的 `/tmp/m2_session.log`。
- **画面很卡**：先确认后台有没有在训练，在 WSL 里执行 `ps aux | grep train_ppo` 查看。
